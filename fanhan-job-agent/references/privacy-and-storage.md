# 隐私与本地存储

## 默认规则

- 原始简历、作品集正文、联系方式和本地会话标识默认留在候选人当前环境。
- 本地生成物统一放在工作区 `.fanhan-job-agent/`，原始简历只读，不覆盖。
- `.fanhan-job-agent/用户求职记忆.md` 只保存候选人确认的求职偏好；`.fanhan-job-agent/Agent平台执行记忆.md` 只保存平台故障、解决办法和复用条件。两者不得混写，也不得上传到工作台、招聘网站或飞书群。
- DOCX 转换得到的参考 PDF 放在 `.fanhan-job-agent/source/`，不得直接上传。岗位专用材料必须先生成并展示同名可编辑 HTML；页面只在当前浏览器的本地存储中保存各段文字草稿，PDF 转换也完全在本地页面完成。用户检查 HTML、亲自导出并回传后，接收脚本只复制该 PDF 的原始字节到 `.fanhan-job-agent/outbox/`；不得从磁盘旧 HTML 再生成一份替代文件。
- 不在终端输出、Git、普通日志或投递记录中保存简历正文、联系方式、Token、Cookie 或表单答案。
- 如果当前目录是 Git 仓库，确认 `.fanhan-job-agent/` 未被跟踪；必要时提醒用户加入本地忽略规则。

## 三种授权不能混用

| 动作 | 所需确认 |
|---|---|
| 本地读取和整理用户刚提供的材料 | 用户发起当前任务即可；不产生外部上传 |
| 把资料交给泛函 | 展示字段、接收方、用途和授权文案后，取得本次清晰同意 |
| 向外部招聘网站填写或上传 | 说明具体网站和数据类别后确认；最终提交前再逐岗位确认 |

泛函授权不等于同意向任意外部网站投递；一次外部岗位确认也不等于后续岗位的批量授权。

## 拒绝与撤回

- 用户拒绝把材料交给泛函时，不调用文件上传和候选人申请接口；公开读取岗位不受影响。
- 用户要求停止推荐或删除档案时，不擅自声称已删除；记录请求并明确交给泛函招聘团队或后续隐私请求接口处理。
