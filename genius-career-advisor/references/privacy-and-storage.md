# 隐私与本地存储

`<workspace>` 是 `scripts/workspace.py resolve` 返回的目录。新档案使用 `.天才职业顾问`。已经存在的本地档案继续留在原目录，不要另建空目录。

## 默认规则

- 原始简历、作品集正文、联系方式和本地会话标识默认留在候选人当前环境。
- 本地生成物统一放在工作区 `<workspace>/`，原始简历只读，不覆盖。
- `<workspace>/用户求职记忆.md` 只保存候选人确认的求职偏好；`<workspace>/Agent平台执行记忆.md` 只保存平台故障、解决办法和复用条件。两者不得混写，也不得放进泛函内推载荷或招聘网站。
- DOCX 转换得到的参考 PDF 放在 `<workspace>/source/`，不得直接上传。岗位专用材料必须先生成同名可编辑 HTML，再由 EgoLite 在同一台机器打开。候选人说改好了后，整页写回这个 HTML。PDF 仍由候选人在页面里亲自生成和下载。交还控制权后，接收脚本只复制这次下载的原始字节到 `<workspace>/outbox/`。再次保存 HTML 会让旧 PDF 失效。不得从磁盘旧 HTML 再生成一份替代文件。
- 不在终端输出、Git、普通日志或投递记录中保存简历正文、联系方式、Token、Cookie、表单答案、内推 webhook 密钥或本地提交标识。
- 如果当前目录是 Git 仓库，确认 `<workspace>/` 未被跟踪。仓库已忽略本地工作区目录和 `grok-bot-referral.json`；不要把 webhook 地址或密钥写进被跟踪的文件。

## 三种授权不能混用

| 动作 | 所需确认 |
|---|---|
| 本地读取和整理用户刚提供的材料 | 用户发起当前任务即可；不产生外部上传 |
| 把资料交给泛函 | 展示字段、接收方、用途和授权文案后，取得本次清晰同意 |
| 向外部招聘网站填写或上传 | 用户选择具体岗位前说明网站、数据类别和提交模式；岗位专属简历预览确认后只对该岗位生效 |

泛函授权不等于同意向任意外部网站投递；一次外部岗位授权也不等于后续岗位的批量授权。默认自动提交只绑定当前选岗记录、当前岗位专属材料、字段集合和最终动作；任一变化都会使授权失效。用户明确要求本人提交时必须改为手动模式。

## 交给泛函

把材料交给泛函是候选人另行提出的可选步骤，不是外部申请或简历定制后的默认下一步。

- 只有候选人逐字同意授权文案后，才把本次材料 POST 到操作者本机配置的 Grok Bot webhook。HTTP 200 只表示材料已交给泛函招聘团队，并会保存在 Twenty 招聘 CRM。
- Webhook 地址和密钥只来自环境变量 `FANHAN_GROK_BOT_WEBHOOK_URL` 与 `FANHAN_GROK_BOT_WEBHOOK_KEY`，或未被 Git 跟踪的 `<workspace>/grok-bot-referral.json`。两项要一起配置。缺失时告诉操作者，不要向候选人索取。
- 不再调用工作台候选人入库接口，也不再查询申请状态或招聘通知卡片。公开读取 `GET /api/public/jobs` 只在候选人要求查看泛函开放岗位时用于展示和匹配。

## 拒绝与撤回

- 用户拒绝把材料交给泛函时，不运行内推 `submit`，也不调用已停用的工作台入库接口。外部找岗和申请不受影响。只有候选人要求时才公开读取泛函岗位。
- 用户要求停止推荐或删除档案时，不擅自声称已删除；记录请求并交给泛函招聘团队处理。
