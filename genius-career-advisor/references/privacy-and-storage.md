# 隐私与本地存储

`<workspace>` 是 `scripts/workspace.py resolve` 返回的目录。新档案使用 `.天才职业顾问`。已经存在的本地档案继续留在原目录，不要另建空目录。

## 默认规则

- 原始简历、作品集正文、联系方式和本地会话标识默认留在候选人当前环境。
- 本地生成物统一放在工作区 `<workspace>/`，原始简历只读，不覆盖。
- `<workspace>/用户求职记忆.md` 只保存候选人确认的求职偏好；`<workspace>/Agent平台执行记忆.md` 只保存平台故障、解决办法和复用条件。两者不得混写，也不得上传到招聘网站。
- DOCX 转换得到的参考 PDF 放在 `<workspace>/source/`，不得直接上传。岗位专用材料必须先生成并展示同名可编辑 HTML；页面只在当前浏览器的本地存储中保存各段文字草稿，PDF 转换也完全在本地页面完成。用户检查 HTML、亲自导出并回传后，接收脚本只复制该 PDF 的原始字节到 `<workspace>/outbox/`；不得从磁盘旧 HTML 再生成一份替代文件。
- 不在终端输出、Git、普通日志或投递记录中保存简历正文、联系方式、Token、Cookie 或表单答案。
- 如果当前目录是 Git 仓库，确认 `<workspace>/` 未被跟踪。不要把候选人材料写进被跟踪的文件。

## 三种授权不能混用

| 动作 | 所需确认 |
|---|---|
| 本地读取和整理用户刚提供的材料 | 用户发起当前任务即可；不产生外部上传 |
| 向外部招聘网站填写或上传 | 用户选择具体岗位前说明网站、数据类别和提交模式；岗位专属简历预览确认后只对该岗位生效 |

一次外部岗位授权不等于后续岗位的批量授权。默认自动提交只绑定当前选岗记录、当前岗位专属材料、字段集合和最终动作；任一变化都会使授权失效。用户明确要求本人提交时必须改为手动模式。本技能不读取或投递工作台岗位，也不把材料交给 Grok Bot。

## 拒绝

- 用户要求投工作台岗位或内推时，说明本技能不做这两件事。外部找岗和申请不受影响。
- 用户要求删除本地档案时，只删除本地工作区里的文件，不声称已经删除工作台或 Grok Bot 上的记录。
