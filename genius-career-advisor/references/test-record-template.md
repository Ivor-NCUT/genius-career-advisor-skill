## 场景 0：档案就绪后直接找岗

- [ ] 用户只说“帮我找适合的工作”，没有限定渠道
- [ ] `source_catalog.py --self-test` 通过，且默认 `requires_user_confirmation` 为 false
- [ ] `external_jobs.py --self-test` 通过，默认结果不包含 JobRadar 或出海聘
- [ ] 档案可匹配后直接搜索，没有先展示渠道表，也没有询问增删渠道
- [ ] 没有向用户展示来源类型、访问门槛、推荐原因或风险
- [ ] 会员主导来源、JobRadar 和出海聘没有进入默认岗位推荐
- [ ] 默认没有读取泛函开放岗位
- [ ] 同一次搜索尝试了多个公开平台，并检索了公司招聘官网；官网职位可以出现在同一份清单里
- [ ] 岗位发现未依赖右侧栏浏览器加载，也没有调用系统默认浏览器

- [ ] 读不到的官网页面不会让整次搜索失败，也没有编造该站点的职位
- [ ] 全部岗位使用同一职业档案统一去重和排序
- [ ] 首轮直接给出可挑选的岗位清单；网站名或链接只出现在岗位自身

## 场景 B：真实成功

- [ ] 搜索前已建立 `职业经历.md`、`profile.json` 和有效 `profile-status.json`
- [ ] 用户看过匹配点、缺口和风险后明确选择岗位
- [ ] Skill 给出针对该 JD 的简历修改建议，而不是通用建议
- [ ] 第一份候选人可见成稿是可编辑 HTML，并已在 Codex 侧边栏展示
- [ ] 用户检查或修改 HTML，并亲自点击“导出 PDF”；回传文件已原字节接收，Agent 没有从磁盘 HTML 重新生成 PDF
- [ ] 已生成并检查完整的岗位专用 HTML/PDF，二者同名且 PDF 不早于 HTML
- [ ] PDF 名称符合 `姓名-目标公司-目标岗位-YYYYMMDD-vN.pdf`，没有沿用旧目标公司
- [ ] `<workspace>/selected-external-job.json` 与当前公司、职位和链接一致
- [ ] 全程只使用一个 EgoLite TaskSpace，未打开系统默认浏览器或 Playwright
- [ ] 登录/扫码/验证码由用户接管；上传不稳定时，Skill 只给出当前岗位专用 PDF 链接，用户拖入右侧申请页
- [ ] 已从顶部到底部扫描完整申请表，并记录所有文字、选择、文件和链接字段；不是只读当前可见区域
- [ ] 每个自动填写字段都已重新读取复核；被页面清空或无法验证的字段没有被描述为“已填好”
- [ ] 存在人工步骤时，已一次性输出全部字段的手工填写清单，包含 `字段名｜值/答案｜状态`，必填项在前
- [ ] 清单汇总的检测、已填并复核、请复制、待回答和请上传数量与逐项清单一致
- [ ] 选岗记录包含 `submission_mode`，且默认值为 `auto`
- [ ] 提交指纹绑定岗位、URL、材料哈希、字段集合、模式和最终动作
- [ ] 自动模式在 `verify` 通过后只点击一次最终按钮
- [ ] 手动模式把同一 TaskSpace 交给用户，没有代替用户点击
- [ ] Agent 只凭明确成功证据记录 `success`；不明确时记录 `submission_outcome_unknown`
- [ ] `submission_outcome_unknown` 没有触发重试
- [ ] 本地记录包含成功证据
- [ ] 外部申请终态写入后停在本地记录，没有自动进入泛函授权，也没有直接启动面试辅助
- [ ] 只有候选人明确要求把材料交给泛函后才展示授权文案；拒绝、沉默或含糊答复没有提交
- [ ] 送达成功只说明材料已交给泛函招聘团队；没有把招聘话题群通知、工作台申请号或旧匹配分说成成功信号
- [ ] 送达成功后没有自动开始面试辅导；用户未主动要求时没有开始提问
