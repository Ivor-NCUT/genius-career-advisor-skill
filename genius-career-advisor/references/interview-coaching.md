# 岗位面试准备与交互练习

这是一条可选流程，不改变搜岗、简历 PDF 和投递确认。候选人主动要求准备面试、开始练习，或明确确认已经进入真实面试阶段时启用。投递结束、放弃投递、材料已送达或用户说“继续”都不能自动启动。

## 输入

先复用这些已有材料，只询问其中仍然缺失的信息：

- 目标公司、岗位、JD 和岗位链接或岗位 ID
- 已投递的简历版本和 `职业经历.md`
- `candidate_memory.py` 里已确认的故事库
- 面试邀请里的轮次、形式、时间和语言

轮次暂时未知时写“待确认”。没有邀请或候选人确认，不能编造一面、二面或三面。准备材料不能改写已投递简历，也不能补造业绩。

## 一份岗位一份目录

```text
<workspace>/interview/<job-key>/prep.md
```

`job-key` 优先用规范化后的岗位详情链接。只有岗位编号时，必须带上公司或来源，避免不同招聘系统里相同编号写到同一份材料。`prep.md` 是唯一交付文件。在对话里先说明准备重点，再给出这份完整 Markdown。不要生成 HTML，也不要运行渲染脚本。

## 五个模块

1. **公司与岗位简报**：业务、产品、用户、目标团队、岗位关键任务、本轮形式，以及“为什么这家公司/岗位”。联网事实写来源链接、核验日期，并标明已核验、未确认或推测。不写长篇公司沿革。
2. **JD 与经历对应表**：每一行都是“JD 要求 → 本人的具体经历和来源 → 可以证明的个人贡献 → 证据缺口”。团队成果和个人贡献分开。初版只写最重要的 3–5 项能力和 2–3 个案例。
3. **重点问题及追问**：自我介绍与动机、简历深挖、业务或技术实战、明显缺口。每题必须关联当前 JD 或具体经历，并写回答要点和可能追问。面经只作为带来源、日期和岗位的题型线索，不能写成必考。初版约 6–10 题。
4. **练习与反馈**：生成准备材料时只写“尚未开始练习”。没有真实回答时，不写模拟反馈、分数或进步记录。
5. **反问清单**：围绕成功标准、入职任务、协作方式、资源和当前困难，帮助候选人判断机会是否适合自己。

## 生成材料和开始练习

这两件事分开。生成文档之后，候选人没有明确说开始练习，就不要连续提问。

开始练习后：

1. 一次只问一道题，等候选人回答。证据含糊时最多追问两次。
2. 反馈必须引用这次回答中的原话或具体问题，只给一个优先改进动作。
3. 参考表达只能重排已经确认的事实。回答里没有的数字，标成缺口，不补造。
4. 用 `candidate_memory.py record-practice` 记录。需要区分岗位时加可选的 `--job-key` 和 `--round`。旧命令不带这两项仍然有效。
5. 只替换 `prep.md` 里“练习与反馈”模块。公司简报、对应表、问题和反问清单保持不动。然后把更新后的完整 Markdown 交给候选人。
6. 练习中新说出的经历可以记成待核实素材。未经候选人确认，不能写进已确认事实或故事库。

分数仍可按原有 1–5 分写入记忆文件，只观察表达变化，不解释为录取概率。

## 故事库和面后复盘

故事库仍从 `职业经历.md` 整理为情境、任务、行动、结果，候选人确认后用 `add-story --confirmed` 写入。团队成果不能自动写成个人贡献，缺失结果不补造。

真实面试结束后，记录被问问题、实际回答、面试官追问和候选人自己的判断。没有逐字稿也可以复盘。不能把候选人的感觉写成面试官结论。

当前版本不做录音处理、复杂评分校准、薪资谈判或 Offer 对比。
