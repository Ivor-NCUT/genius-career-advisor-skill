# V1 执行契约

## 范围

- 运行入口：Codex 中的 `$fanhan-job-agent`。
- 岗位来源：主 Skill 同一轮读取泛函岗位，并根据候选人偏好从内置来源快照推荐 3–5 个外部渠道；用户确认后，本 Skill 才访问这些渠道并与泛函岗位统一排序。Bonjour、Watcha 可作为直接申请候选；JobRadar 只作岗位发现源，跟随其链接进入的不同来源页不构成稳定平台适配。
- 岗位发现：Bonjour 和 Watcha 优先通过公开页面数据/feed 读取；JobRadar 如实返回登录/会员限制。不得把浏览器超时当作无岗位。
- 浏览器：只在选岗后使用 Codex 内置浏览器查看详情、登录和申请，不得退回系统默认浏览器。
- 单岗位闭环：职业资产建档、搜索、解释匹配、用户明确选岗、针对性建议、生成岗位专用简历、查重、准备或预填表单、必要时由用户拖入已检查 PDF、用户本人提交或放弃、识别结果、写本地记录，再回到主 Skill 取得泛函入库授权并核验飞书通知。面试辅助只作可选提示，不自动启动。

本契约是安全骨架，不代表来源清单中的网站都已通过稳定投递验收。Bonjour 是首个直接投递候选，Watcha 为第二顺位。

默认找岗时，只访问用户确认的 3–5 个外部来源，并逐一返回真实状态；需要登录、会员或暂不可用时继续其他已确认来源。未尝试不能写成无结果。

Watcha 的公开岗位来源是 `https://watcha.cn/jobs-api/v1/public/teams`，查岗页是 `https://watcha.cn/study/jobs`。查岗页为 SPA；初始 HTML 标题或 canonical 可能显示共学营，不能据此判断岗位为空。先验证公开接口中的 `teams/jobs`，接口失败后才检查渲染出的岗位数量或岗位卡片。

Bonjour 的公开职位页会随 HTML 返回岗位数据，V1 直接解析该数据，不依赖浏览器逐卡加载。JobRadar 的完整岗位与投递入口受登录/会员限制；未获得合作 API 前只报告限制，不读取其后台数据库绕过付费墙。

## 选岗门禁

- 搜索前必须存在 `$职业资产` 生成的职业主档，五维首次职业咨询均已由候选人确认，且 `profile-status.json` 与当前 `profile.json` 哈希一致并标记为 `可匹配`。
- 用户选岗后必须先完成 1–2 个基于当前 JD 的针对性问题并把答案写回长期主档；`material_gate.py` 验证咨询记录确实进入简历变更后，才能生成岗位专用材料。
- 当前页面、历史标签页或 Agent 自己打开的页面都不是用户意图证据。
- 用户必须在看过匹配点、缺口和风险后明确选择单个岗位；随后生成 `.fanhan-job-agent/selected-external-job.json`。
- 记录必须绑定公司、职位、岗位链接、申请链接和选择时间。记录缺失或与当前页面不一致时，禁止发送个人数据、上传材料或准备提交。
- 选岗后必须先展示针对性建议，再生成并立即展示 `姓名-目标公司-目标岗位-YYYYMMDD-vN.html`。用户检查、修改并亲自导出同名 PDF 后才能进入申请页；原始简历、仅转换格式的 PDF、旧公司版本、名称不匹配或没有同名 HTML 的 PDF 都不能进入申请页。

## 两个确认点

1. **个人数据发送确认**：输入联系方式等个人数据或上传材料前，必须说明数据类别、目标网站和用途，并获得当次确认。
2. **最终提交确认**：表单准备完成后展示当前岗位摘要；用户检查后亲自点击最终按钮。旧确认和批量授权不能代替当前点击。

选岗记录、岗位、申请页面、材料内容、字段集合或最终动作发生变化时，确认立即失效。

## 模式与状态

- 当前唯一验收模式是 `辅助投递`；`托管代投` 延后。
- `skipped`：重复岗位或页面不支持，必须有原因。
- `awaiting_confirmation`：表单已准备，等待用户检查。
- `user_declined`：用户拒绝，绝不提交。
- `success`：用户已提交且有明确成功证据。
- `failed`：流程失败或结果无法确认，必须有原因。

成功证据只接受明确成功文案、申请编号或平台状态。按钮消失、页面跳转或请求超时不等于成功。

## 隐私与失败策略

- 日志只保存时间、来源、公司、职位、链接、状态、是否确认、成功证据和原因；不得写入材料正文、表单答案、联系方式、凭据或登录态。
- 登录、扫码、验证码和不稳定的文件上传交给用户接管。
- 选岗后的内置浏览器不可用时记 `failed`，不得打开系统浏览器；岗位发现脚本失败时只标记对应来源 `unavailable` 并继续其他来源。
- 页面不支持时记 `skipped` 或 `failed`，继续推荐别的岗位。
- 结果不明确时记 `failed: submission_outcome_unknown`，不得重复提交。
