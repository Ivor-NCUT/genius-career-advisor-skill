# V2 执行契约

## 范围

- 运行入口：Codex 中的 `$fanhan-job-agent`。
- 首次由候选人决定岗位方向、城市、行业、企业类型、届别、工作类型和排除项；不得把维护者或示例候选人的偏好写成默认值。
- 岗位来源：主 Skill 同一轮读取泛函岗位，并根据候选人偏好从来源快照推荐 3–5 个外部渠道；用户确认渠道后才访问。
- 岗位发现：Bonjour 和 Watcha 优先读取公开页面数据/feed；JobRadar 如实返回登录或会员限制。不得把浏览器超时当作无岗位。
- 浏览器：用户选岗后只使用 `$ego-browser` 的当前 TaskSpace/Page API 查看详情、登录、填写和提交；不得启动系统 Chrome、Playwright 或旧版 EgoLite API。
- 单岗位闭环：职业建档、找岗、解释匹配、用户选岗、定制简历、用户预览并回传 PDF、查重、EgoLite 填表、自动或手动提交、结果核验和本地记录。

本契约不承诺来源清单中的所有网站都能稳定投递。单一来源失败不得阻塞其他来源，也不能为了完成提交绕过登录、验证码、付费墙或反自动化限制。

## 选岗与材料门禁

- 搜索前必须存在 `$职业资产` 生成的职业主档，且 `profile-status.json` 与当前 `profile.json` 哈希一致并标记为 `可匹配`。
- 页面、标签页和 Agent 推荐都不是投递授权。用户必须看过匹配点、缺口和风险后明确选择具体岗位。
- 选岗记录绑定公司、职位、岗位链接、申请链接、选择时间和 `submission_mode`。默认模式是 `auto`；用户明确说本人点击时是 `manual`。
- 进入申请页前必须生成岗位专属可编辑 HTML。用户检查或修改、亲自导出并回传同名 PDF 后，`material_gate.py` 才能把它登记为本次申请简历。
- 岗位、JD、选岗记录、HTML、PDF 或提案变化时旧指纹失效，必须重新检查。

## 授权模型

用户选择具体岗位时，先展示目标网站、会填写的数据类别和默认提交模式。用户继续选岗并确认岗位专属简历，构成对**当前岗位与当前材料**的填写和提交授权：

- `auto`：EgoLite 完成表单、回读字段并通过 `confirmation_gate.py verify` 后，自动点击一次当前指纹绑定的最终按钮。
- `manual`：EgoLite 完成同样的填写与回读后交接同一 TaskSpace，由用户本人点击。

授权不能扩张到其他岗位。登录、验证码、扫码、风控、敏感字段、未知事实、来源冲突、无法回读的必填字段或过期指纹都会强制暂停。

## 指纹与状态

确认指纹至少绑定公司、职位、岗位 URL、申请 URL、选岗时间、提交模式、职业档案、岗位提案、可编辑 HTML、确认 PDF、表单字段集合和最终按钮动作。

- `skipped`：重复岗位或页面不支持，必须有原因。
- `awaiting_confirmation`：手动模式等待用户动作，或流程遇到需要用户决定的字段。
- `user_declined`：用户拒绝，不提交。
- `success`：当前岗位发生一次提交且有明确成功证据。
- `failed`：流程失败或结果无法确认，必须有原因。

成功证据只接受成功文案、申请编号或招聘系统申请状态。按钮消失、页面跳转或请求超时不等于成功；结果不明记录 `failed: submission_outcome_unknown`，禁止再次点击或自动重投。

## 隐私与记录

- 登录、短信/图形验证码、扫码和浏览器权限提示由用户在 EgoLite 中接管；不得保存密码、Cookie、Token、验证码或登录态。
- 日志只保存时间、来源、公司、职位、链接、状态、提交模式、成功证据和原因；不得写入材料正文、表单答案、联系方式或凭据。
- 新生成的开放题答案只能使用已确认职业事实和当前 JD。需要新增事实或涉及敏感决定时先询问用户。
- 完成或失败后按 [EgoLite 网申执行](egolite-application.md) 结束或保留任务空间。
